# Synchri v0.5.3 — Reliable CLI discovery from the macOS app

This patch release restores automatic launch of connected Claude Code,
Codex, and GitHub Copilot CLIs when Synchri is opened from Finder or
LaunchServices. Connected runtimes now resolve through a deterministic,
desktop-safe search path instead of falling back to pasted prompts because
macOS started the app with a minimal system `PATH`.

**Status: implemented and verified.**

## Baseline

- **Previous version: v0.5.2**, released from `codex/release-v0.5.2` and
  merged to `main` at `3add12e`.
- This patch ships as **v0.5.3** from branch
  `codex/fix-desktop-cli-discovery`.

## Scope

- [x] The native macOS entry point prepares a deterministic desktop `PATH`
  before starting Synchri, including executable locations from connected
  runtime records, standard per-user tool directories, common version-manager
  shims, Homebrew, `/usr/local/bin`, and the Codex binary bundled with ChatGPT.
- [x] Connected runtime records are read defensively and read-only; failed,
  unknown, mismatched, or non-executable records cannot alter discovery.
- [x] Managed launches, planning launches, connection tests, resume canaries,
  and recovery resumes pin the resolved absolute executable while preserving
  prompt and resume placeholders.
- [x] Shell startup files are never sourced, keeping desktop launch
  deterministic and avoiding arbitrary shell initialization side effects.
- [x] The frozen-sidecar build now runs a Finder-equivalent smoke test with a
  temporary connected Claude CLI and refuses to package an app that would
  regress to manual prompts.
